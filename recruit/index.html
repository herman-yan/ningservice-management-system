使用说明与已知限制

三步跑通

① 粘贴岗位 JD → 点「解析并生成规则」→ 在规则表里核对 / 调权重 / 设硬门槛；② 从聊天窗口复制简历粘贴到「快速入库」（或拖入 ZIP / 单份文件、点顶部「载入看板做 JD 匹配」）→ 自动入库并打分；③ 看右侧排名、在「入库简历库」标记状态与备注、展开证据、打印或导出。

省掉逐个点开、下载（推荐给 HR）

最省力的一条：把「数据源」里那个书签按钮拖到浏览器书签栏，以后在 BOSS 点开任意候选人的在线简历页，点一下书签栏的「抓简历」，当前页面文字就自动送到本页简历库并打分 —— 不用下载、不用复制粘贴、不用切回来。每条简历只在本机浏览器入库、不上传。附件 PDF 若平台不展开正文，用 BOSS 官方批量下载打成 ZIP 拖进本页；也可开启「监视下载文件夹」，以后下载到该目录的简历自动读入。每位 HR 各自拖一次书签即可，不需要在任何一台固定电脑上登录。

快速入库与入库简历库（对话场景）

在 BOSS 企业版与候选人沟通、拿到附件简历 / 在线简历后（平台自带「索要简历 / 下载 / 发送至邮箱」功能），复制简历文本粘贴到左侧「快速入库」框 —— Ctrl+V 即自动解析、去重、打分并写入本机入库简历库，右侧排名立刻更新；下载的 PDF / DOCX 可直接拖入，官方批量导出的 ZIP 也会自动增量入库。
库内可为每人标记待筛 / 已邀约 / 面试中 / 已录用 / 淘汰并写备注，支持按状态筛选、单条移除、导出 JSON 备份与导入恢复。重复简历（同一手机号 / 邮箱 / 姓名或全文一致）自动跳过，不再重复计分。
与顶部「候选人简历库」的区别：顶部是随站点发布的 862 人结构化名册（只读，可搜索 / 筛选 / 导出 / 一键载入看板）；本面板是你自己导入的简历全文，只存在本机浏览器，不上传、不随站点发布。演示数据与站点名册均不写入本机入库简历库。

官方导出 ZIP（推荐路径）

在 BOSS 企业版「人才库 / 沟通中」勾选候选人 → 点【下载简历】→ 选 PDF，得到打包 ZIP；猎聘按套餐的简历下载额度同样可批量导出。把 ZIP 直接拖进左侧即可：自动展开逐个解析，支持中文（UTF-8 / GBK）文件名、嵌套压缩包，自动跳过目录、系统附带文件、加密与超限条目。平台导出的 CSV / JSON 结构化数据包会按行 / 按记录拆成多份候选人；含候选人字段表头的才拆，普通简历式 CSV 不会被误拆。
ZIP 全程用浏览器原生 DecompressionStream 解压，不引第三方库、不联网、不上传。加密压缩包（导出时设了密码）无法解析，会逐条提示；ZIP64 超大包与单份超 8MB 的条目会跳过，请在平台分批导出。

多人汇总发布（把大家的简历共享到本站）

本站是纯静态页面，多个 HR 无法各自写入同一份库。共享走「汇总 → 发布」两步：① 各 HR 把批量下载的简历拖进本页入库后，点「5 · 多人汇总发布」里的「导出我的增量」，把 增量_*.json 发给汇总人；② 汇总人把所有人增量一起拖进虚线框 → 自动按手机号 / 邮箱 / 姓名去重合并 → 点「生成站点文件」下载 resumes.json（默认隐去姓名与联系方式）→ 交给管理员运行仓库里的 publish_resumes.py 一键推送，全员刷新本站即见同一份。发布脚本只更新简历库数据文件，不动其它内容，并会自动校验格式、备份旧文件、轮询线上确认生效。

打分口径

硬门槛不满足 → 一票否决并归 0 分。其余规则按「完全命中 1.0 / 原文部分命中 0.6 / 未命中 0」乘权重，归一化到 0–100。简历未体现的项目按 0 分计入分母，但单列「待核实」并生成追问，不会写死成「不具备」。置信度= 可判定项权重占比，越低说明简历信息越缺。

已知限制

• 离线为纯关键词 + 同义词词典匹配，无语义理解，同义表述可能漏判，请在规则表补关键词。
• .zip / .docx 依赖浏览器原生 DecompressionStream（Chrome / Edge 103+）；不支持时请另存为 .txt。加密 ZIP、ZIP64、单份超 8MB 条目会被跳过并逐条提示。
• .pdf 需联网从 CDN 加载 pdf.js；离线状态请粘贴文本或转 .txt / .docx。ZIP 内 PDF 较多时逐份解析较慢，建议导出为文本格式。
• 图片简历 / 扫描件 不支持 OCR，需先转成文本。
• 中文简历版式自由，姓名 / 年限 / 学历可能识别不到，此时如实标注「未识别」而非猜测。
• 入库简历库存于本机浏览器 IndexedDB（不支持时降级 localStorage / 内存），不上传服务器；公开站点上其他人打开看到的是空库。换设备、清浏览器数据或用无痕模式前请先「导出备份」。
